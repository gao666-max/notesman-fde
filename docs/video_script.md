# 产出 4：5 分钟讲解视频脚本

## 0:00-0:25 一、你看到了什么

笔记侠编辑团队的核心矛盾不是"AI 能不能写"，是编辑的注意力该花在哪儿。

一份 90 分钟的逐字稿有 97 个段落。编辑现在的流程是：通读全部 97 段，手动标注，搭结构，分段写，反复返工。最费时间的不是写作，是在大量口语对话里找到那几个真正值得写的观点。

负责人说过：我不要一个把录音转成文章的工具，我需要 AI 帮编辑更快找到值得写的观点，保留证据，形成可编辑的初稿。最后一层判断，仍然由编辑完成。

这就是起点。

## 0:25-1:05 二、你设计了什么

四个 Agent，各做一件事：

Agent 1 观点提取——逐字稿进去，10 到 15 个结构化观点节点出来，每个带证据原文、时间戳、置信度，自动归类。

Agent 2 历史复用判断——观点和历史笔记匹配，标出哪些能引用、哪些是陷阱。比如题目里 note_02 和当前逐字稿是同一场，Agent 2 会标记"同一场，不复用"。

Agent 3 内容生成——编辑选好观点和大纲，生成 500 到 800 字的可编辑初稿。

Agent 4 事实核查——草稿逐条比对原始证据，输出红黄绿三级核查报告。

核心分工：AI 做信息处理——提取、匹配、比对。编辑做判断——什么值得写、什么不能写、怎么说才对。

交互上也体现这个分工：编辑不在聊天框里跟 AI 对话，而是在可视化面板上看到 AI 预处理好的观点卡片，拖拽、排序、选择。编辑做的是决策，不是打字。

## 1:05-2:35 三、你做出了什么 · Demo

【打开页面，预置演示数据已加载】

中间四象限——纵轴置信度，横轴热点相关性。绿色右上角直接采用，黄色中间建议复核，红色左下角必须确认。一秒钟判断优先级。

左边卡片库分五个抽屉——高维思想是认知升级，当下解答是实用价值，信息差是你不知道但该知道的。Agent 1 自动归类。还有弱信号和低置信度两个抽屉，AI 拿不准的留给编辑。

【点击一张卡片】

点开能看到证据原文、时间戳、因果链——嘉宾的"因为 A 所以 B 导致 C"自动提取出来，编辑一眼看到逻辑有没有断点。

【导入 SRT】

现在导入真实的 SRT 文件。Agent 1 分析大概 30 到 50 秒。分析完四象限和卡片库换成新数据，标题和章节结构也自动生成。

【拖拽两张卡片到工作区 → 点生成全文草稿】

Agent 3 把卡片展开成一篇 600 多字的文章。标题来自嘉宾原话，编辑可以直接改。

点事实核查——Agent 4 输出红黄绿三级报告，每个问题给具体的改写建议。

导入历史笔记——Agent 2 自动判断复用。

## 2:35-3:20 关键取舍

两个关键取舍。

第一个，Agent 2 的同一场检测——这是我实际踩的坑。开始是一个 prompt 同时判断"是不是同一场"和"能不能复用"，结果 LLM 认出是同一场但还给 95 分判复用。因为"内容高度匹配"同时触发了加分和拒用两个相反动作。Prompt 怎么改都不行。最后拆成两阶段——Phase 1 只做同一场检测，代码层直接排除，Phase 2 再做语义匹配。教训是：不要靠 prompt 死磕内在矛盾，该改架构就改架构。

第二个，为什么没有 RAG 外检。方案里规划了完整路径，但 48 小时内搭向量数据库风险太高。当前用 LLM 训练知识做交叉验证，诚实标注"这个我没见过，需要编辑核实"，不冒充实时检索。

## 3:20-4:15 如果有更多时间

三件事。

第一，给 Agent 4 接上 RAG 外检——像"终生收入下降五分之一"这种嘉宾引用但没指明来源的数据，系统能自动搜索可信来源做验证。

第二，Agent 2 规模化——上百篇笔记时加向量初筛，先缩到 20 篇再让 LLM 精细判断。

第三，协作功能——多个编辑同时在线，筛选、搭建、拍板分工协作，把每个人的判断差异记录下来变成可追溯的信息。

谢谢。
